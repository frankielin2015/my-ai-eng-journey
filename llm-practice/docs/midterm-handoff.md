## What was built

A single RAG-lite pipeline (`src/midterm/triage.py`) that exercises every
load-bearing concept from Weeks 1–4 in one place. It's a support-ticket
classifier that:

1. Sanitizes the input (`</` escape — Week 3 ladder rung 2)
2. Embeds the query via local Ollama (`nomic-embed-text`, one-map rule)
3. Retrieves top-3 similar past tickets (hand-written cosine + sort)
4. Renders v1 or v2 prompt (`str.replace`, never `str.format` — W3)
5. Calls the LLM (retry-with-stricter-constraint — W2 production pattern)
6. Extracts the CoT fence (`split("</thinking>")[-1].strip()` — W3)
7. Validates with Pydantic (`TicketTriage` model — W2)
8. Returns `{category, severity, reasoning, similar_ticket_ids, scores, prompt_version}`

## What the oracle review found and fixed (13 findings)

An independent `@oracle` pass caught two BLOCKERS, five IMPROVEMENTs, and
six NITs in the first skeleton. Highlights:

- **BLOCKER (taxonomy drift):** the original TODO 1 hint listed
  `category: "performance"` and `severity: "critical"`, but the actual
  corpus, prompts, and reference impl use `["billing", "shipping", "account",
  "bug", "feature_request"]` and `["low", "medium", "high", "urgent"]`. A
  learner following the hint literally would have built a model that
  rejects 100% of valid LLM answers and looked like "the model is broken."
  Fixed by aligning the hint to the real taxonomy.
- **BLOCKER (model-output vs. result schema):** the original TODO 1
  required all 6 fields, but both prompts only ask the LLM for 3
  (`category`, `severity`, `reasoning`). The other 3 (`similar_ticket_ids`,
  `scores`, `prompt_version`) are pipeline-derived. Fixed by giving those
  three `default_factory=list` / `= "v1"` defaults and adding a hint that
  names the data-flow direction ("model can't know similar_ticket_ids —
  it doesn't run the retrieval").
- **IMPROVEMENT (imports):** added `math`, `Literal`, `Field`,
  `ValidationError` to the imports so the learner doesn't hit `NameError`
  before reaching any LLM concept.
- **IMPROVEMENT (stubs):** every `pass` is now a
  `raise NotImplementedError("TODO N: <hint>")`. Failures now name the
  TODO directly instead of producing confusing `TypeError: NoneType` errors.
- **IMPROVEMENT (missing tests):** added 4 acceptance tests — 2 for the
  Pydantic schema (TODO 1), 2 for `render_prompt` (TODO 7). Total: 11 tests
  up from 7.
- **IMPROVEMENT (reference divergence):** the reference impl uses
  different internal signatures. Added a disclosure at the top of
  `triage.py` so the learner doesn't try to copy-paste from the reference.
- **IMPROVEMENT (TODO 4 format):** pinned the save format to "ticket
  dicts augmented with a `vector` key" — matches the on-disk
  `tickets_corpus_embedded.json` and `week4/semantic_search.py`.
- **NIT (over-specified hints):** trimmed the verbatim cosine formulas
  and CoT-fence code from TODOs 5 and 8 — the lesson is recall, not
  copy-paste. Pointed the learner at `week3/lab_sentiment.py:122–123`
  instead.
- **NIT (sort key):** TODO 6 hint now uses `key=lambda p: p[0]` to
  avoid a `TypeError` on score ties.
- **NIT (cosine range):** removed the implied `[0, 1]` constraint on
  `scores` — cosine math is `[-1, 1]`, this embedder yields `~0–1` in
  practice.

## Two bugs found and fixed during the build (worth remembering)

1. **`format="json"` kwarg was out of scope.** The W2 quirks doc
   describes a retry-with-constraint production pattern that works
   WITHOUT specifying any `response_format`. Removed the kwarg.

2. **CoT fence extraction was missing.** The v2 prompt asks the model
   to put reasoning inside `<thinking>...</thinking>` then output JSON.
   Without `split("</thinking>")[-1].strip()` first, `json.loads`
   chokes on the leading `<thinking>` tag. Added the extraction.

Both bugs were surfaced by diagnostic output, not vibes.
